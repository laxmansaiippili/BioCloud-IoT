Cloud Computing Architecture & Key Role in Healthcare

Why Cloud Computing is Essential (The Core Problem Solved)

Traditional patient monitors are confined to the hospital bedside. An ESP32 microcontroller has only 520 KB RAM and cannot store months of patient history or serve multiple concurrent users. Furthermore, hospital Wi-Fi networks use private IPs behind firewalls (NAT), preventing family members at home or work from connecting. Cloud Computing solves this by providing a globally-accessible, highly scalable, and secure central backbone.

5-Layer Edge-to-Cloud System Architecture

Layer 1: Edge Sensing
ESP32 DevKit + DS18B20 digital sensor acquires body temperature every 2–5s, performs CRC validation, and packages JSON telemetry payloads.
Layer 2: Cloud Edge Proxy
Cloudflare Global Anycast Edge routes traffic via 300+ cloud data centers, terminates SSL/TLS certificates, and bypasses NAT firewalls.
Layer 3: Cloud Compute (PaaS)
Cloud REST API ingests telemetry, runs real-time threshold evaluation (<37.5° Normal, 37.5°–37.9° Warning, ≥38.0° Critical), cooldown & deduplication.
Layer 4: Cloud DBaaS Persistence
Centralized persistent cloud storage preserves patient records, historical time-series temperatures, relative authorization links, and HIPAA audit trails.
Layer 5: Cloud Pub/Sub & Real-Time Distribution
Server-Sent Events (SSE) multiplexing pushes live telemetry & emergency siren alarms to doctor dashboards and authorized relatives' smartphones across public 4G/5G mobile networks worldwide.

Cloud Service Models (SPI Framework) Implemented

Cloud Model Implementation in BioCloud IoT Key Benefit
PaaS (Platform as a Service) Cloud Telemetry Ingestion API, Rules Evaluation Engine, Real-Time SSE Streamer Zero infrastructure maintenance; handles sensor streams concurrently.
DBaaS (Database as a Service) Persistent Cloud JSON/NoSQL Store, Time-Series Telemetry Table, HIPAA Audit Logs Refreshing or changing devices never loses patient medical history.
SaaS (Software as a Service) Role-Based Dashboards (Admin, Doctor, Patient Relative) rendered in any browser Instant access on mobile/desktop without installing native client apps.

Key NIST Cloud Computing Characteristics

  • Broad Network Access: Relatives can monitor patients on 4G/5G cellular data from anywhere in the world.
  • Multi-Tenancy & Resource Pooling: A single cloud instance securely isolates multiple hospital wards, doctors, and patient families via strict RBAC.
  • On-Demand Self-Service: Doctors and relatives register, view telemetry, and receive alarms without human administrative intervention.

ESP32 & DS18B20 Hardware Wiring Guide

Connect your physical DS18B20 temperature sensor to the ESP32 using these exact pinouts:

DS18B20 Sensor Wire -----> ESP32 Pin ------------------------------------------------ 1. RED Wire (VCC) -----> 3V3 (3.3V) 2. BLACK Wire (GND) -----> GND 3. YELLOW Wire(Data) -----> GPIO 4 (Pin D4) CRUCIAL: Place a 4.7kΩ Resistor between 3V3 (RED) and GPIO 4 (YELLOW)! (Band colors: Yellow - Violet - Red - Gold)

Arduino IDE Quick Steps:

  1. Install OneWire and DallasTemperature libraries in Arduino IDE.
  2. Open firmware/biocloud_temp_esp32.ino.
  3. Enter your Wi-Fi name (AUS-ROBOTICS) and password at the top.
  4. Verify server URL is set to: http://192.168.205.219:3000/api/telemetry
  5. Select board ESP32 Dev Module, choose your COM port, and click Upload!

Once uploaded, open Serial Monitor at 115200 baud to see readings streaming live to this dashboard and connected mobile phones!
